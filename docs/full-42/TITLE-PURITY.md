# Optional written title majority

Only topic candidates receive this extra title veto. Existing explanation, claim, critic, locality, confidence and card decisions remain authoritative. A failed or unknown majority drops title_written and leaves the existing scraped-title fallback. No new Today hold or public card field is introduced.

The snapshot reader binds the candidate's item_id, metric_date, market and pinned detect run to exactly one cluster in that market-day's first ready understand_cluster_plan. It decodes every saved batch using the producer decoder, checks the complete written cluster IDs, and compares the target cluster's planned and published member IDs. Missing plans, duplicate IDs, ambiguous references or incomplete writes yield unknown. Other dates, pooled clusters and item totals are never substitutes.

N is the complete unique planned membership, including assigned probability-zero members. The reader obtains full stored source content for at most the existing twelve-post evidence bound, preferring shared evidence IDs so source-version conflicts can be detected. A suppressed, missing, unread or over-context source remains in N and stays unknown. No creator, locality, citation or probability filter reduces N. The content snapshot describes this read, not an unretained copy of the original fit input.

The single existing title support call keeps its original aggregate verdict and reason. Its title-only schema also requests member_checks containing post_id, supported/partial/unsupported verdict and an exact source quote. The shared support system and schema for all other uses are unchanged. A positive member requires the checker's semantic supported verdict and a non-empty quote validated against that member's full stored text. Word overlap alone never provides support. Non-positive, missing, duplicate, foreign-ID, malformed and hash-conflicting receipts remain unknown. Unsupported is not silently converted into proof of an unrelated story.

The original aggregate title support must pass. The extra veto passes only when 2*S>N, where S is validated supported membership. Every other member remains unknown; a bounded subset never becomes N. If the unchanged model cap, accounting day, deadline, output limit or model error prevents proof, the written title is absent. No second title call, per-member call loop, cap increase or retry increase is added.

After all absorption, the final pack's shared producer posts are checked again against the frozen full text. A changed source makes the optional title unknown. The final pack hash is bound into the actual title request and the receipt. A successful receipt replaces its pre-call state and records a proved-majority reason.

Private receipts retain plan and cluster references, detect run, full N, membership and content hashes, read times, title/hash, actual response and reason hashes, semantic verdicts and validated Unicode character span offsets with quote hashes. Complete member arrays are recovered from the referenced append-only producer plan, rather than duplicated. Source text and raw model responses are not duplicated into run counts. A later source read must match its stored hashes before a span can be audited; a changed or unavailable historical source remains unproven.

Encoded receipt size uses the run store's JSON-string counts encoding and the outer JSON encoding. Each receipt is bounded to 16,384 bytes, the projected group to 1,000,000 bytes, and final counts with receipts to a conservative 9,000,000 bytes below the 10 MB sink limit. A receipt bound affects only the optional title. The final check occurs before brief/check insertion and removes unauditable topic titles without altering explanations or card/hold decisions. These private receipts go to title_majority_receipts in run counts. Public cards and held items have no added private fields. Historical briefs without a producer snapshot receive no manufactured majority verdict.

Verification uses offline saved-plan and DuckDB boundaries plus fake checker responses. These checks prove mechanics, not native semantic accuracy, warehouse availability, runtime latency or real provider cost.
