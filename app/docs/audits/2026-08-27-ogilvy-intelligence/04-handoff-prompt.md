# Implementation handoff prompt

    Redesign directive: Redesign 42 as Ogilvy Intelligence using the approved “Red Thread” direction.

    This is a replacement of the current Google-derived identity and dashboard architecture. Do not refine the existing shell.

    Primary user:
    An Ogilvy strategist who needs to detect what matters, understand why, inspect proof, compare options, and turn one evidence-backed decision into a brief.

    Primary sequence:
    Signal → Why now → Receipts → Precedent → Possible response → Brief.

    Brand:
    Use “42 / Ogilvy Intelligence”. Remove every visible Google name, mark, colour, font request, dot system, loading metaphor, and co-brand reference. Use the approved internal Ogilvy wordmark only if the real asset is supplied. Never redraw it.

    Visual direction:
    Build “The Red Thread”, an editorial intelligence canvas where Ogilvy red traces real evidence relationships and intersection markers encode source agreement, cross-market spread, historical recurrence, or contradiction. Use ink black, warm paper, white, and Ogilvy red. Semantic amber and green exist only for evidence readiness.

    Architecture:
    1. Briefing
    2. Discover
    3. Compare
    4. Build
    5. Fieldwork

    Historical Intelligence appears contextually where precedent changes a decision and remains available through the deeper archive.

    Visual grammar:
    1. Editorial lead
    2. Evidence ledger
    3. Comparison strip

    No fourth grammar without design review.

    Hard constraints:
    1. No Google identity or external Google Fonts request.
    2. No gradients, glow, glass, decorative dots, route colour lanes, floating pills, or idle animation.
    3. No generic chat box as the hero.
    4. Default radius 0. A 2 pixel radius is permitted for form controls.
    5. Two elevations only.
    6. Eight text sizes maximum, all tokenized.
    7. Red has one meaning: evidence lineage and the primary action.
    8. Every claim shows ready, thin, contradictory, or unchecked state.
    9. Unsupported audience remains explicitly unavailable.
    10. Empty states name the checked run and closed window.
    11. At 390 pixels, the first recommendation starts within 720 pixels.
    12. Keyboard, focus, zoom, reflow, reduced motion, contrast, and 48 pixel targets are release gates.

    Required deliverables before implementation:
    1. Information architecture and route migration.
    2. Desktop and mobile wireframes for Briefing, Discover, Compare, Build, Research, Evidence Room, and Fieldwork.
    3. Token sheet for type, colour, spacing, rules, focus, and state.
    4. Content hierarchy for ready, thin, contradictory, unchecked, no-discovery, loading, error, and stale states.
    5. Component retirement map naming every Google, route wall, card, theme, motion, and legacy vendor surface to delete.
    6. Browser acceptance tests and screenshot references.
    7. Staging batches with rollback.

    Before coding, present two distinct Red Thread compositions and get Albert’s approval of one. Then follow strict test-first implementation. After each batch, run the anti-slop acceptance test and a Rams audit. A batch that still looks like an unnamed AI dashboard is rejected even if its tests pass.
